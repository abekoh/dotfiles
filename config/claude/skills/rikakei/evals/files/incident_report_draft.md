# 障害報告

標記の件について報告する。

今回の障害は、6月30日の深夜にデプロイされた、認証サービスの接続プールの設定値が本番環境の想定同時接続数を大幅に下回る値のままになっていた新バージョンが原因ではないかと思われる。デプロイ後しばらくは問題が顕在化しなかったが、朝のアクセスピーク時に接続が枯渇し、ログイン処理が概ね失敗する状態となった。尚、監視アラートに就いては設定されていたものの、通知先のチャンネルが既に使用されていないものであった為、気付くのが遅れた模様である。

復旧対応としては、まず暫定的に接続プールの設定値の変更が行われ、その後、サービスの再起動が実施された。この対応により、11時頃には概ね正常な状態に復旧したものと考えられる。

再発防止策としては、次の諸点を心に留めておくことも重要である。設定値のレビュープロセスの強化を実行する可能性も考慮すべきであるし、又、監視通知先の定期的な棚卸しをすることも可能であると思われる。
