# GitHub Actions ワークフローの composite action による共通化

## 概要

本ドキュメントでは、複数リポジトリで重複していたGitHub Actionsのワークフロー定義をcomposite actionを用いて共通化した事例について説明する。

## 背景

当社では複数のGoアプリケーションのリポジトリが存在しており、それぞれのリポジトリにCIワークフローが定義されていた。各ワークフローにはGoのセットアップ、依存関係のキャッシュ、lintの実行、テストの実行という共通の処理が含まれていた。これらの定義はリポジトリごとにコピーされており、以下の問題が発生していた。

第一に、Goのバージョンアップの際に全リポジトリのワークフローファイルを修正する必要があり、修正漏れが発生することがあった。第二に、golangci-lintの設定変更やバージョン更新についても同様に全リポジトリへの反映が必要であった。第三に、リポジトリによって微妙に設定が異なっており、CIの挙動に一貫性がなかった。

## 対応内容

上記の問題を解決するため、composite actionを利用して共通処理を一つのリポジトリに集約した。composite actionは複数のstepをまとめて一つのactionとして定義できる機能である。再利用可能ワークフロー(reusable workflow)という選択肢も存在するが、ジョブ単位ではなくstep単位で組み込める柔軟性を考慮し、composite actionを採用した。

共通アクション用のリポジトリを新規作成し、action.ymlにGoのセットアップ、キャッシュ設定、golangci-lintの実行を定義した。各リポジトリのワークフローからは、usesディレクティブでこの共通アクションを参照する形に変更した。バージョン管理はgitのタグを用いて行い、各リポジトリは特定のバージョンを指定して利用する。

## 結果

共通化の結果、以下の効果が得られた。Goのバージョンアップ作業は共通アクションリポジトリの1箇所の修正で完了するようになった。各リポジトリのワークフローファイルの行数は平均して60行から15行程度に削減された。CIの挙動が全リポジトリで統一され、リポジトリ間の設定差異に起因する問題が解消された。

## 今後の課題

タグの更新を各リポジトリに反映する作業が手動であるため、Renovateなどのツールによる自動化を検討する。また、テスト実行部分についてはリポジトリごとの差異が大きく共通化できていないため、引き続き検討を行う。
