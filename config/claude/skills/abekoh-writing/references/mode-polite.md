# 丁寧モード(です・ます)

技術解説記事向けのモード。Zenn・会社ブログなど、読者に何かを紹介・解説・提案する記事で使う。

## 語尾ルール

- 地の文はです・ます基調。ただし単調にならないよう、以下を織り交ぜる:
  - 「〜しております」「〜となっています」などのやや丁寧な補助動詞
  - 体言止めや「〜が必要です」→「〜が必要になります」などの変化
- **箇条書き内は常体・体言止め**。です・ます調のまま箇条書きに入れない
- 見出しは常体・体言止め
- 脚注・注釈も常体寄りでよい

## 読者との距離感

- 解説記事の一人称は「筆者」。「私」はプロダクト紹介の文脈(「私たちが開発している〜」)くらい
- 読者への提案・呼びかけで段落やセクションを締める:
  - 「ぜひ検討してみてください」
  - 「気を付けておきましょう」
  - 「自身の環境にあったものを選定しましょう」
  - 「採用する際は要件に合うのか綿密に調査・実験することをおすすめします」
- 主観的な主張は「〜と筆者は考えます」で明示的に自分の意見だと断る
- 記事の締めは「参考になれば幸いです」系+今後の展望(「それも折を見て紹介できればと思います」)

## お手本(実記事からの抜粋)

### はじめに: 個人的文脈からの導入

> 我が家には数年前に組んだ「GeForce RTX 3080搭載のゲーミングPC」があるわけですが、最近はPCゲームをそこまでやらず、それなりのGPUあるのにもったいないなという状態です。
>
> 最近はローカルLLMの性能も良くなり、せっかくなのでそれなりのGPU積んだゲーミングPCをAIマシンにして有効活用できないかな、と思い。それなら自宅以外、クラウドからも呼び出せると嬉しいだろうなーと妄想してました。
>
> そのはじめの一歩として、IPSec VPNで自宅ネットワークとGoogle Cloud VPCを繋ぐ仕組みを整えてみました。そのログです。

ポイント: 「〜なわけですが」の語り出し、「と思い。」の言い切り、「だろうなーと妄想」のゆるさ、最後に「そのログです」で範囲宣言。

### 問いかけ→答えのリズム

> 外部パッケージ変更のシナリオはgo.mod, go.sumのハッシュ値も変更になり、レイヤーキャッシュが効かなくなるのは頷けますが、それ以外のシナリオはなぜ遅くなったのでしょう？
>
> 答えは、キャッシュの保存・準備に時間を要してしまったためです。

ポイント: 疑問形で1段落、答えで1段落。読者を巻き込みながら進める。

### 買い物・出来事の語り(感情込み)

> 入手したのはこちらRTX830。希望小売価格なんと101,200円(税込)！
> …この値段だと流石にな、とは思いましたが、メルカリで探すと中古2万円程度の出品がたくさんあったので購入。業務用の安定高機能なルータが2万はお買い得な気がします。

ポイント: 「なんと〜！」の驚き、「…」からの本音、「な気がします」の緩い着地。

### 主張の締め方(筆者は考えます)

> このように、Given-When-Thenで分割して記述でき、何をどうテストしているかがわかりやすいコードになったと思います。
> 勿論実際のプロダクトのコードではこれより煩雑になると思われますが、Given-When-Thenパターンをできるだけ守っておくことである程度複雑性を抑えられると筆者は考えます。

ポイント: 成果を控えめに評価→留保を認める→「と筆者は考えます」で主観だと明示。

### 注意喚起の呼びかけ

> 実際のユースケースとして、CIでコンテナイメージのビルド・プッシュを走らせる時はコード変更を含む場合のほうが多いと思います。特に考えずキャッシュを入れただけで実は逆効果、という可能性もありますので気を付けておきましょう。
